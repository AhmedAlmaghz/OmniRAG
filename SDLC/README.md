## 1. الرؤية العامة (Product Vision)

تطبيق **Hybrid RAG (Retrieval-Augmented Generation)** متقدم وثنائي اللغة (عربي/إنجليزي) يُمكّن المستخدمين من جلب بياناتهم من مصادر متعددة ومتنوعة، ومعالجتها بذكاء اصطناعي متطور، ثم الاستعلام عنها بلغة طبيعية مع ضمان **العزل الكامل** و**الخصوصية التامة** لكل مستخدم. يجمع النظام بين **البحث الدلالي** (Semantic Search) و**البحث المعجمي** (Lexical/Keyword Search) في بنية هجينة لتحقيق أعلى دقة في الاسترجاع.

## 2. المكدس التقني (Technology Stack)

### 2.1 نماذج الذكاء الاصطناعي

| الطبقة | النموذج | الوصف |
|---|---|---|
| **التضمين (Embedding)** | `gemini-embedding-2` | نموذج تضمين متعدد الوسائط يدعم تضمين الصور والفيديو والصوت والمستندات إلى جانب النصوص. يُنتج متجهات بأبعاد 3072. يلتقط المعنى الدلالي عبر أكثر من 100 لغة |
| **الاستدلال السريع** | `gemini-3.5-flash-lite` | نموذج متعدد الوسائط منخفض التأخير وفعّال التكلفة محسّن للإنتاجية العالية ومهام التحليل السريع. أسرع نموذج في فئة 3.5 بسرعة 350 رمزاً في الثانية |
| **الاستدلال المتقدم** | `gemini-3.6-flash` | نموذج من سلسلة Gemini 3 عالي القدرة للاستدلال متعدد الوسائط، يقدم أداءً أفضل في البرمجة والعمل المعرفي مع كفاءة أعلى في استهلاك الرموز مقارنة بـ Gemini 3.5 Flash |

### 2.2 معالجة المستندات (Document Processing)

| الأداة | الوصف |
|---|---|
| **Mistral Document AI (OCR 4)** | يوفر معالجة مستندات على مستوى المؤسسات تجمع بين تقنية OCR واستخراج البيانات المنظمة المتقدم، مع دعم متعدد اللغات وتعليقات توضيحية وسير عمل قابلة للتكيف لجميع أنواع المستندات. يدعم 170 لغة مع صناديق إحاطة وتصنيف كتل ودرجات ثقة |
| **Unstructured Transform API** | يجلب معالجة مستندات بمستوى إنتاجي كخادم MCP مع القدرة على تحويل أكثر من 60 نوع ملف إلى بيانات منظمة. يوفر مكونات مفتوحة المصدر لاستيعاب ومعالجة الصور والمستندات النصية مثل PDF وHTML وWord وغيرها، حيث تدور حالات الاستخدام حول تبسيط وتحسين سير عمل معالجة البيانات لنماذج اللغة الكبيرة |

### 2.3 قواعد البيانات

| قاعدة البيانات | الدور |
|---|---|
| **Qdrant** | قاعدة بيانات متجهية عالية الأداء للبحث الدلالي (Vector Search) — تُخزن التضمينات وتُجري البحث بأقرب الجيران (ANN) |
| **Neon Postgres** | قاعدة بيانات علائقية Serverless تعتمد على PostgreSQL — تُخزن البيانات الوصفية (Metadata)، وبيانات المستخدمين، وسجلات المحادثات، والإعدادات، مع دعم `pgvector` للبحث الهجين |

### 2.4 النشر والبنية التحتية

| المكوّن | التقنية |
|---|---|
| **الاستضافة** | Vercel (Edge Functions + Serverless) |
| **الإطار** | Next.js 15+ (App Router) مع React Server Components |
| **اللغة** | TypeScript |
| **المصادقة** | NextAuth.js / Clerk مع Row-Level Security (RLS) |
| **إدارة المهام الخلفية** | Inngest / Trigger.dev للمهام غير المتزامنة |
| **التخزين المؤقت** | Vercel KV (Redis) |

**تفصيل خيارات Mistral Document AI:**
- يستخرج النص مع الحفاظ على بنية المستند وتسلسله الهرمي ويحافظ على التنسيق مثل العناوين والفقرات والقوائم والجداول، مع إمكانية تبديل تنسيق الجداول بين markdown وHTML
- يقدم صناديق إحاطة وتصنيف كتل ودرجات ثقة مضمّنة لكل منطقة

**تفصيل خيارات Unstructured Transform:**
- يدعم التقسيم والتضمين وإثراء الصور والجداول من واجهة برمجية أو واجهة مستخدم منخفضة التعليمات البرمجية
- يفرض التحكم في الوصول على مستوى الأجزاء (Chunk-level) بحيث يحمل كل جزء أذونات المستند الأصلي

#### 4.6.2 إعدادات التقسيم (Chunking Settings)

| الإعداد | الوصف |
|---|---|
| `chunkSize` | حجم الجزء (256 — 2048 رمز) — قابل للتعديل بمنزلق |
| `chunkOverlap` | نسبة التداخل بين الأجزاء (0% — 30%) |
| `chunkingStrategy` | استراتيجية التقسيم: حسب الفقرات / حسب الجمل / حسب العناوين / دلالي (Semantic) / هجين |
| `preserveStructure` | الحفاظ على بنية الجداول والقوائم أثناء التقسيم |
| `languageDetection` | كشف اللغة التلقائي لكل جزء (عربي/إنجليزي/مختلط) |

#### 4.6.3 إعدادات البحث الهجين (Hybrid Search Configuration)

| الإعداد | الوصف |
|---|---|
| `semanticWeight` | وزن البحث الدلالي (0.0 — 1.0) |
| `lexicalWeight` | وزن البحث المعجمي (0.0 — 1.0) |
| `fusionAlgorithm` | خوارزمية الدمج: Reciprocal Rank Fusion (RRF) / Weighted Sum / Convex Combination |
| `topK` | عدد النتائج المُسترجعة (1 — 20) |
| `reranking` | تفعيل إعادة الترتيب (Re-ranking) باستخدام نموذج Cross-Encoder |
| `scoreThreshold` | الحد الأدنى لدرجة التطابق لعرض النتائج |
| `mmrDiversity` | تنوع النتائج عبر Maximal Marginal Relevance |


### 7.2 نموذج البيانات (Data Model — Neon Postgres)

```sql
-- جدول المستخدمين
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL UNIQUE,
    email TEXT NOT NULL UNIQUE,
    name TEXT,
    preferred_language TEXT DEFAULT 'ar', -- ar | en
    settings JSONB DEFAULT '{}',
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- جدول المصادر
CREATE TABLE sources (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES users(tenant_id),
    type TEXT NOT NULL, -- file | url | api | integration
    name TEXT NOT NULL,
    config JSONB, -- تكوين خاص بنوع المصدر
    sync_schedule TEXT, -- cron expression
    last_synced_at TIMESTAMPTZ,
    status TEXT DEFAULT 'active',
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- جدول المستندات
CREATE TABLE documents (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES users(tenant_id),
    source_id UUID REFERENCES sources(id),
    title TEXT,
    content TEXT, -- النص الكامل المستخرج
    content_tsv TSVECTOR, -- فهرس البحث النصي الكامل
    language TEXT, -- ar | en | mixed
    metadata JSONB,
    processing_engine TEXT, -- mistral | unstructured | internal
    status TEXT DEFAULT 'pending', -- pending | processing | indexed | failed
    file_path TEXT,
    page_count INTEGER,
    token_count INTEGER,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- جدول الأجزاء (Chunks)
CREATE TABLE chunks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES users(tenant_id),
    document_id UUID NOT NULL REFERENCES documents(id),
    content TEXT NOT NULL,
    content_tsv TSVECTOR,
    chunk_index INTEGER NOT NULL,
    page_number INTEGER,
    section_title TEXT,
    language TEXT,
    token_count INTEGER,
    embedding_id TEXT, -- معرف النقطة في Qdrant
    metadata JSONB,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- جدول المحادثات
CREATE TABLE conversations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES users(tenant_id),
    title TEXT,
    mode TEXT DEFAULT 'private', -- private | hybrid | general | analysis
    model TEXT DEFAULT 'gemini-3.6-flash',
    collection_ids UUID[], -- المجموعات المستهدفة
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- جدول الرسائل
CREATE TABLE messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES users(tenant_id),
    conversation_id UUID NOT NULL REFERENCES conversations(id),
    role TEXT NOT NULL, -- user | assistant | system
    content TEXT NOT NULL,
    citations JSONB, -- [{chunk_id, score, snippet}]
    model_used TEXT,
    tokens_used JSONB, -- {input: n, output: n}
    feedback TEXT, -- positive | negative | null
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- تفعيل RLS على كل الجداول
ALTER TABLE sources ENABLE ROW LEVEL SECURITY;
ALTER TABLE documents ENABLE ROW LEVEL SECURITY;
ALTER TABLE chunks ENABLE ROW LEVEL SECURITY;
ALTER TABLE conversations ENABLE ROW LEVEL SECURITY;
ALTER TABLE messages ENABLE ROW LEVEL SECURITY;

-- سياسة RLS موحدة
CREATE POLICY tenant_isolation ON sources
    USING (tenant_id = current_setting('app.current_tenant')::UUID);
-- (تُكرر لكل جدول)

-- فهرس البحث النصي الكامل للعربية والإنجليزية
CREATE INDEX idx_chunks_fts ON chunks USING GIN(content_tsv);
CREATE INDEX idx_documents_fts ON documents USING GIN(content_tsv);
```

### 9.1 مصفوفة استخدام النماذج

| السيناريو | النموذج | السبب |

| **تصنيف واستخراج** | `gemini-3.5-flash-lite` | يُفضل مستوى التفكير الأدنى للمهام الحساسة للتأخير أو مهام التصنيف والاستخراج البسيطة لتحقيق أقصى كفاءة |
| **توليد إجابات RAG عادية** | `gemini-3.6-flash` | نموذج العمل اليومي لأعمال البرمجة والمعرفة والمدخلات متعددة الوسائط وسير العمل الوكيلي |
| **أسئلة متابعة وتلخيص** | `gemini-3.5-flash-lite` | للمهام الأخف التي لا تتطلب استدلالاً عميقاً |

# 🔌 إضافة طبقة MCP — وثيقة التوسعة الشاملة لـ OmniRAG

---

## ما هو MCP ولماذا هو ضروري لـ OmniRAG؟

البروتوكول MCP (Model Context Protocol) هو بروتوكول مفتوح يُقيّس طريقة توفير السياق لنماذج اللغة الكبيرة — فكّر فيه كـ USB-C لتطبيقات الذكاء الاصطناعي، يوفر طريقة موحدة لربط النماذج بمصادر البيانات والأدوات المختلفة.

منذ إطلاقه، استمر MCP في النمو بمعدل مذهل — حيث تجاوز كل من TypeScript SDK و Python SDK عتبة المليار تنزيل إجمالي، وأصبح البروتوكول ركيزة البيانات والتفاعلية لسير عمل الوكلاء الذكيين.

في 2026، يعمل MCP جنباً إلى جنب مع معيار ناشئ ثانٍ هو **A2A (Agent-to-Agent Protocol)** من Google. حيث يتحكم MCP في كيفية اتصال الوكلاء بالأدوات ومصادر البيانات، بينما يتحكم A2A في التواصل المباشر بين الوكلاء أنفسهم — والبروتوكولان متكاملان وليسا متنافسَين.

---

## أحدث مواصفة: MCP 2026-07-28

أحدث مواصفة MCP (2026-07-28) تجعل البروتوكول **عديم الحالة تماماً (Stateless)** على مستوى البروتوكول — لا مزيد من تعريف الجلسة (initialize handshake) ولا تثبيت العميل بمعرف Mcp-Session-Id.

خادم MCP البعيد الذي كان يحتاج سابقاً إلى جلسات لزجة (sticky sessions) ومخزن جلسات مشترك وفحص عميق للحزم عند البوابة، يمكنه الآن العمل خلف موازن تحميل round-robin عادي.

على صعيد TypeScript، يُشحن البروتوكول الجديد كحزمتين جديدتين: `@modelcontextprotocol/client` و`@modelcontextprotocol/server`، كلتاهما بالإصدار 2.0، بينما يستمر خط `@modelcontextprotocol/sdk` القديم لخوادم الإصدار 2025.

## 1. طبقة MCP Gateway — القلب التقني

### 1.1 الدور والمهام

بوابة MCP هي طبقة وسيطة مركزية لإدارة وتأمين وتوسيع نطاق الاتصالات بين تطبيقات الذكاء الاصطناعي وخوادم MCP المتعددة.

عندما يُرسل عميل طلب `tools/call`، تحدد البوابة خادم MCP المسؤول عن الأداة وتُعيد توجيه الطلب وفقاً لذلك، مما يدعم تنسيق متعدد الخوادم حيث يمكن لتطبيق ذكاء اصطناعي واحد الوصول إلى وظائف من خلفيات عديدة.

## 2. المصادر والموارد (MCP Resources) — مكوّن منفصل عن الأدوات

في بروتوكول MCP: **الأدوات (Tools)** هي إجراءات قابلة للتنفيذ مع مخططات مدخل/مخرج صريحة وإفصاح عن الآثار الجانبية. **الموارد (Resources)** هي مصادر بيانات قابلة للقراءة يمكن للعميل جلبها لسياق النموذج. **التعليمات (Prompts)** هي قوالب تفاعل مُعرّفة مسبقاً تُقيّس المهام.

## 5. نظام المصادقة لخوادم MCP (OAuth 2.0 — RFC 8707)

تُصنّف مواصفة MCP يونيو 2025 خوادم MCP رسمياً كـ **OAuth Resource Servers**، وتُلزم عملاء MCP بتطبيق **Resource Indicators** وفق RFC 8707، مع صفحة مخصصة لأفضل ممارسات الأمان.

يجب على العملاء الآن التحقق من معامل `iss` في استجابات التفويض وفق RFC 9207، وهو تخفيف منخفض التكلفة لفئة من هجمات الخلط (mix-up attacks) الأكثر شيوعاً في نمط نشر MCP ذو العميل الواحد والخوادم المتعددة.

```typescript
// /lib/mcp/auth/oauth-manager.ts
// متوافق مع مواصفة 2026-07-28 — RFC 8707 + RFC 9207

import { 
  OAuthClientProvider,
  ResourceIndicatorValidator 
} from '@modelcontextprotocol/server';

export class MCPOAuthManager {

  // بدء تدفق OAuth مع Resource Indicators
  async initiateOAuthFlow(params: {
    tenantId: string;
    serverId: string;
    serverResourceUri: string; // RFC 8707: Resource Indicator
    scopes: string[];
    callbackUrl: string;
  }) {
    // التحقق من Resource Indicator لمنع Token Misuse
    const validated = await ResourceIndicatorValidator.validate({
      resourceUri: params.serverResourceUri,
      requestedScopes: params.scopes,
    });

    // إنشاء PKCE challenge (إلزامي)
    const { codeVerifier, codeChallenge } = await generatePKCE();

    // حفظ الحالة مع tenant isolation
    await this.storeOAuthState({
      tenantId: params.tenantId,
      serverId: params.serverId,
      codeVerifier,
      resourceUri: params.serverResourceUri,
      nonce: crypto.randomUUID(),
    });

    return buildAuthorizationUrl({
      ...validated,
      codeChallenge,
      state: await encryptState(params.tenantId, params.serverId),
    });
  }

  // معالجة callback مع التحقق من iss (RFC 9207)
  async handleOAuthCallback(params: {
    code: string;
    state: string;
    iss: string; // إلزامي في المواصفة 2026-07-28
  }) {
    // التحقق من iss لمنع هجمات الخلط
    const { tenantId, serverId } = await decryptState(params.state);
    const storedState = await this.getOAuthState(tenantId, serverId);

    // RFC 9207: التحقق من أن iss يطابق Authorization Server المتوقع
    await validateIssuerParameter({
      receivedIss: params.iss,
      expectedIss: storedState.expectedIssuer,
    });

    const tokens = await exchangeCodeForTokens({
      code: params.code,
      codeVerifier: storedState.codeVerifier,
      resourceIndicator: storedState.resourceUri,
    });

    // تخزين الرمز مشفراً مع tenant isolation
    await this.storeTokensSecurely(tenantId, serverId, tokens);
  }

  // تجديد الرمز تلقائياً مع Resource Binding
  async refreshTokenWithResourceBinding(tenantId: string, serverId: string) {
    const tokens = await this.getTokens(tenantId, serverId);
    const config = await this.getServerConfig(serverId);

    const newTokens = await refreshAccessToken({
      refreshToken: tokens.refreshToken,
      resource: config.resourceUri, // RFC 8707
    });

    await this.storeTokensSecurely(tenantId, serverId, newTokens);
    return newTokens;
  }
}
```

```typescript
    const { tenantId, userMessage, model, maxIterations = 5 } = params;

    // جمع أدوات MCP النشطة للمستخدم
    const mcpTools = await MCPClientPool
      .getActiveTools(tenantId, params.enabledMCPServers);

    // أدوات RAG الداخلية
    const ragTools = this.buildRAGTools(tenantId);

    const result = await generateText({
      model: google(model),
      system: await this.buildSystemPrompt(tenantId, params.mode),
      messages: await this.buildMessageHistory(params.conversationId),
      tools: { ...ragTools, ...mcpTools },
      maxSteps: maxIterations, // حلقة الوكيل
      onStepStart: async (step) => {
        // تسجيل كل خطوة للمراقبة
        await this.logAgentStep(tenantId, step);
      },
      onStepFinish: async ({ toolCalls, toolResults }) => {
        // التحقق من صلاحيات الأدوات ذات الآثار الجانبية
        for (const call of toolCalls) {
          if (SIDE_EFFECT_TOOLS.includes(call.toolName)) {
            await this.requestUserConfirmation(tenantId, call);
          }
        }
      },
    });

    return {
      response: result.text,
      steps: result.steps,
      citations: this.extractCitations(result.steps),
      toolsUsed: this.extractToolsUsed(result.steps),
      tokensUsed: result.usage,
    };
  }

  private buildRAGTools(tenantId: string) {
    return {
      search_knowledge_base: tool({
        description: 'البحث في قاعدة المعرفة الخاصة',
        parameters: z.object({
          query: z.string(),
          topK: z.number().default(5),
        }),
        execute: async ({ query, topK }) => {
          return hybridSearch({ tenantId, query, topK });
        },
      }),
    };
  }
}
```

## 7. تجمع عملاء MCP (MCP Client Pool)

تُستخدم `createMcpHandler(factory)` من `@modelcontextprotocol/server` كنقطة دخول HTTP للإصدار v2 التي تخدم مواصفة 2026-07-28 لكل طلب — وتخدم أيضاً بشكل افتراضي حركة مرور عام 2025 من خلال الأسلوب عديم الحالة المُثبَّت.

```typescript
// /lib/mcp/client-pool.ts
import { Client } from '@modelcontextprotocol/client';
import { StreamableHTTPClientTransport } from '@modelcontextprotocol/client/streamable-http';

// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
// كل عميل Stateless — متوافق مع 2026-07-28
// لا sessions — كل طلب مستقل بالكامل
// tenant_id يُمرر دائماً ضمن معاملات الأداة
// ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

export class MCPClientPool {

  private static cache = new Map<string, CachedClient>();

  static async getClient(serverId: string, tenantId: string): Promise<Client> {
    const cacheKey = `${serverId}:${tenantId}`;
    
    // فحص الكاش (مع TTL قصير لأن العملاء stateless)
    const cached = this.cache.get(cacheKey);
    if (cached && !this.isExpired(cached)) {
      return cached.client;
    }

    const config = await getServerConfig(serverId, tenantId);
    const tokens = await getMCPTokens(serverId, tenantId);

    const transport = new StreamableHTTPClientTransport(
      new URL(config.endpoint),
      {
        // رمز الوصول مع Resource Binding (RFC 8707)
        authProvider: async () => ({
          type: 'bearer',
          token: await this.getValidToken(serverId, tenantId),
        }),
        // Headers الجديدة في مواصفة 2026-07-28
        headers: {
          'Mcp-Client-Id': `omnirag-${tenantId}`,
        },
      }
    );

    const client = new Client(
      { name: 'omnirag-client', version: '2.0.0' },
      { capabilities: { tools: {}, resources: {}, prompts: {} } }
    );

    await client.connect(transport);

    // كاش لمدة قصيرة (الـ Stateless لا يحتاج حالة)
    this.cache.set(cacheKey, { 
      client, 
      expiresAt: Date.now() + 60_000 // 60 ثانية
    });

    return client;
  }

  // جلب الأدوات المتاحة من خوادم MCP النشطة
  static async getActiveTools(
    tenantId: string, 
    serverIds: string[]
  ): Promise<Record<string, any>> {
    const tools: Record<string, any> = {};
    
    const clients = await Promise.allSettled(
      serverIds.map(id => this.getClient(id, tenantId))
    );

    for (let i = 0; i < clients.length; i++) {
      if (clients[i].status === 'fulfilled') {
        const serverTools = await clients[i].value.listTools();
        
        for (const t of serverTools.tools) {
          // نطاق الأداة: serverId__toolName لتجنب التعارض
          const scopedName = `${serverIds[i]}__${t.name}`;
          tools[scopedName] = this.wrapTool(
            clients[i].value, 
            t, 
            tenantId
          );
        }
      }
    }

    return tools;
  }

  // تغليف أداة MCP مع التحقق من tenant isolation
  private static wrapTool(client: Client, tool: any, tenantId: string) {
    return {
      description: tool.description,
      parameters: tool.inputSchema,
      execute: async (params: any) => {
        // إضافة tenant_id تلقائياً لكل استدعاء
        const result = await client.callTool({
          name: tool.name,
          arguments: { ...params, tenant_id: tenantId },
        });
        
        // تسجيل الاستدعاء في سجل التدقيق
        await MCPAuditLogger.log({
          tenantId,
          toolName: tool.name,
          params: sanitizeParams(params),
          result: summarizeResult(result),
        });
        
        return result;
      },
    };
  }
}
```

## 12. أفضل الممارسات المُطبّقة في طبقة MCP

وفق أفضل ممارسات MCP في الإنتاج: **مسؤولية واحدة** — حد واضح لنطاق كل خادم وحد مصادقة واحد. **مجموعات أدوات محدودة** — أدوات مُركّزة بعقود محددة، يجب تجنب الخوادم الـ "kitchen-sink". **العقود أولاً** — مخططات مدخل/مخرج صارمة، آثار جانبية صريحة، أخطاء موثقة.

وفيما يخص النقل: **stdio للعمليات المحلية** حيث يُولّد العميل الخادم كعملية فرعية، و**Streamable HTTP للخدمات البعيدة والتوسع الأفقي**.

في 2026، يُقلّل اعتماد MCP زمن الاستجابة بنسبة تصل إلى 15% ويزيد الإنتاجية، وتُفضّل المؤسسات MCP للنشر الآمن والقابل للتوسع في RAG والأتمتة والتحليلات.

| الممارسة | التطبيق في OmniRAG |
|---|---|
| **Stateless بالكامل** | كل طلب MCP مستقل — لا sessions — متوافق مع 2026-07-28 |
| **RFC 8707 Resource Indicators** | كل رمز OAuth مُقيّد بـ Resource URI محدد لمنع Token Misuse |
| **RFC 9207 ISS Validation** | التحقق من معامل `iss` في كل تدفق OAuth |
| **Tenant Isolation في كل أداة** | `tenant_id` إلزامي في كل معامل أداة |
| **Audit Log شامل** | تسجيل كل استدعاء أداة مع المدخلات والمخرجات والزمن |
| **Rate Limiting لكل خادم** | حد الاستدعاءات لكل خادم لكل مستخدم |
| **تأكيد الآثار الجانبية** | أي أداة ذات Side Effect تتطلب موافقة صريحة |
| **تشفير الأسرار** | جميع المفاتيح والرموز مُشفّرة بـ AES-256 في قاعدة البيانات |
| **Health Monitoring** | فحص دوري لصحة كل خادم مع تنبيهات الفشل |
| **Scoped Tool Names** | نطاق `serverId__toolName` لتجنب تعارض الأسماء |

---

> **ملاحظة:** طبقة MCP في OmniRAG مصمّمة وفق أحدث مواصفة 2026-07-28 التي جعلت البروتوكول عديم الحالة بالكامل، مما يضمن التوافق مع موازنات التحميل العادية على Vercel دون الحاجة لأي بنية تحتية خاصة. يمكن توسيع هذه الطبقة لتدعم أي من الـ 22,000+ خادم MCP المتاح في السجل الرسمي بإضافة بضعة أسطر إضافة إلى سجل الأدوات.
