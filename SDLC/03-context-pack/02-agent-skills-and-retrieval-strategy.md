# Agent Skills and Retrieval Strategy

يحدّد هذا القسم آلية **الإفصاح التدريجي (Progressive Disclosure)** لمهارات الوكلاء (Agent Skills) في OmniRAG، وكيف يستردّ الوكيل المعرفة عند الطلب من المستودعات المعتمدة دون تحميل نافذة السياق دفعة واحدة. يُكمل هذا القسم ما تم تأسيسه في [بنية السياق وأنواعه الستة](./01-context-architecture-and-six-context-types.md)، ويمهّد لما سيُغطّاه [اقتصاد الرموز والصيانة](./03-token-economics-and-maintenance.md).

## 1. مبادئ التصميم

| المبدأ | التطبيق في OmniRAG |
|---|---|
| **مهارة = حزمة قابلة للتحميل عند الطلب** | كل Skill ملف Markdown منظّم في `/.agents/skills/<name>/SKILL.md` مع مخطّط ثابت، يُحمَّل فقط عندما يُشخّص الوكيل حاجته إليه |
| **حدود واضحة بين الساكن والديناميكي** | المعرفة الساكنة (سياسات الأمان، أنماط RAG) في `AGENTS.md`؛ المعرفة الديناميكية (وثائق MCP، مخططات API، كتيّبات النموذج) في Skills قابلة للاكتشاف |
| **الاسترجاع قبل التوليد** | الوكيل يستعلم فهرس Skills قبل أي قرار معماري، ثم يحمّل المهارة المناسبة ويُدرج تعليماتها في السياق |
| **التوجيه بالنموذج الصغير** | اكتشاف المهارة = نموذج صغير + بحث متّجهي؛ تنفيذ المهارة = نموذج كبير فقط عند الحاجة |
| **العزل والامتثال** | كل Skill مُقيَّد بـ `tenant_id` عند احتوائه على بيانات حساسة، ولا تتسرّب أسرار عبر المهارات المشتركة |

## 2. تشريح المهارة (Skill Anatomy)

كل Skill في OmniRAG يتبع المخطط الموحّد التالي:

```yaml
# /skills/<category>/<skill-name>/SKILL.md (front-matter)
name: <kebab-case-identifier>
version: <semver>
tenant_scope: global | tenant           # هل تختلف البيانات بين المستأجرين؟
trigger_keywords: [<list>]               # كلمات تُفعّل التحميل التلقائي
dependencies: [<skill-names>]            # مهارات يجب تحميلها مسبقاً
token_budget: <int>                      # الحد الأقصى لرموز المهارة
category: ingestion | retrieval | generation | mcp | security | i18n
last_reviewed: <YYYY-MM-DD>
owner: <team-or-person>
```

**البنية الداخلية لـ SKILL.md:**

| القسم | المحتوى | لماذا؟ |
|---|---|---|
| **الوصف** | جملة واحدة: ما الذي تُمكّن المهارة من إنجازه | للفهرسة والاكتشاف |
| **متى تُستخدم** | أنماط الاستعلام / السيناريوهات الدقيقة | لتقليل التحميل الخاطئ |
| **المتطلبات المسبقة** | أدوات، متغيرات بيئية، بيانات اعتماد | يمنع التنفيذ الناقص |
| **الخطوات** | تسلسل إجراءات قابل للتحقق | للوكلاء ولـ evals |
| **معايير النجاح** | مخرجات محدّدة وقابلة للقياس | لإغلاق حلقة التقييم |
| **الأخطاء الشائعة** | ما يجب تجنّبه، الفخاخ المعروفة | يغطّي "مشكلة الـ 80%" |
| **أمثلة** | مدخل/مخرج لكل سيناريو رئيسي | أمثلة Few-Shot |
| **الروابط** | مراجع لوثائق خارجية حية | لتجنّب التكرار في السياق |

## 4. استراتيجية الاسترجاع (Retrieval Strategy)

### 4.1 حلقة الاكتشاف والتحميل

```mermaid
flowchart TD
    A[استعلام الوكيل] --> B{الاستعلام بسيط<br/>وثابت؟}
    B -- نعم --> C[تنفيذ مباشر<br/>من AGENTS.md]
    B -- لا --> D[استعلام فهرس Skills<br/>بنموذج صغير + بحث متّجهي]
    D --> E{تم العثور على<br/>Skill مطابقة؟}
    E -- لا --> F[إجابة "غير معروف"<br/>+ اقتراح إنشاء Skill]
    E -- نعم، بثقة عالية --> G[تحميل SKILL.md<br/>كاملاً ضمن الميزانية]
    E -- نعم، بثقة منخفضة --> H[تحميل الوصف فقط<br/>وطلب تأكيد]
    G --> I[تنفيذ خطوات المهارة]
    H --> J{المستخدم يؤكد؟}
    J -- نعم --> G
    J -- لا --> K[البحث عن بديل]
    I --> L[تسجيل التفعيل<br/>في Skill Usage Log]
```

### 4.2 طبقات الاسترجاع الأربع

| الطبقة | المحتوى | أداة الاكتشاف | زمن الاستجابة المستهدف |
|---|---|---|---|
| **L1 — تعليمات دائمة** | سياسات أمان، أنماط RAG الأساسية، بروتوكولات Tenant | مُضمَّن في `AGENTS.md` دائمًا | 0ms (ساكن) |
| **L2 — فهرس Skills** | عناوين + أوصاف + كلمات محفِّزة لجميع المهارات | بحث متّجهي (gemini-embedding-2) + بحث مفتاحي | < 200ms |
| **L3 — جسم المهارة** | `SKILL.md` الكامل عند التحميل | حقن مباشر في السياق | < 100ms (I/O) |
| **L4 — معرفة حيّة** | وثائق MCP الرسمية، changelog النماذج، حالة Qdrant | استعلام HTTP/API عند الطلب | < 1500ms |

### 4.3 قواعد اختيار المهارة

- **قاعدة الميزانية:** إذا تجاوز مجموع مهارات مطلوبة `token_budget` المُحدّد، يُطبَّق ترتيب أولويات: `security/*` > `mcp/*` > `retrieval/*` > `generation/*` > `ingestion/*` > `i18n/*`.
- **قاعدة التبعية:** لا تُحمَّل `unstructured-transform` دون تحميل `chunker-hybrid` إذا كانت الوجهة تخزين Qdrant.
- **قاعدة الإصدار:** عند تعارض إصدارَين، يُفضَّل الإصدار الأعلى رقمًا فقط إذا كان `last_reviewed` خلال آخر 90 يومًا.
- **قاعدة العزل:** أي Skill في `tenant_scope: tenant` تُحقن بـ `tenant_id` المُتحقَّق منه قبل التحميل.

## 5. الفهرسة والاكتشاف

### 5.1 بنية الفهرس

يُخزَّن فهرس Skills في Neon Postgres بجدول مخصّص:

| العمود | النوع | الوصف |
|---|---|---|
| `skill_id` | TEXT PK | مسار المهارة (مثل `retrieval/hybrid-search-executor`) |
| `category` | TEXT | الفئة الست |
| `title` | TEXT | العنوان المقروء |
| `description` | TEXT(500) | جملة واحدة للمهارة |
| `embedding` | vector(3072) | متجه الوصف + الكلمات المحفِّزة عبر `gemini-embedding-2` |
| `trigger_keywords` | TEXT[] | الكلمات المفتاحية |
| `dependencies` | TEXT[] | المهارات المطلوبة مسبقًا |
| `token_budget` | INT | الميزانية المرصودة |
| `tenant_scope` | TEXT | `global` أو `tenant` |
| `version` | TEXT | إصدار SemVer |
| `last_reviewed` | DATE | تاريخ آخر مراجعة بشرية |
| `enabled` | BOOLEAN | مفتاح التفعيل/التعطيل |

### 5.2 استعلام الاكتشاف

```typescript
// /lib/skills/discovery.ts — نموذج صغير يختار 1-3 مهارات
import { google } from '@ai-sdk/google';

export async function discoverSkills(
  query: string,
  topK: number = 3
): Promise<SkillMatch[]> {
  // 1. بحث متّجهي سريع في فهرس Skills
  const queryEmbedding = await embed(query, 'retrieval_query');
  const candidates = await vectorSearch('skills_index', queryEmbedding, topK * 3);

  // 2. إعادة ترتيب بمصنف خفيف
  const reranked = await classify(query, candidates);

  // 3. تطبيق قواعد الميزانية والتبعية
  return enforceBudgetAndDeps(reranked, topK);
}
```

**معايير النجاح لاكتشاف المهارة:**

| المعيار | الهدف | القياس |
|---|---|---|
| دقة الاستدعاء Top-1 | ≥ 85% | eval على 200 استعلام مرجعي |
| زمن الاكتشاف P95 | < 300ms | مقياس في Observability |
| معدّل التحميل الخاطئ | < 10% | مراجعة بشرية أسبوعية |
| تغطية المهارات المُستخدمة | 100% | فحص آلي شهري |

## 6. إدارة دورة حياة المهارة

### 6.1 سير العمل

```
[إنشاء] → [مراجعة PR] → [بناء فهرس] → [نشر] → [مراقبة] → [إهمال]
   ↑                                                       │
   └───────────────────── تحديث/إصلاح ─────────────────────┘
```

| المرحلة | المالك | المخرج | SLA |
|---|---|---|---|
| **الإنشاء** | مهندس مالك الفئة | ملف `SKILL.md` + تحديث الفهرس | — |
| **المراجعة** | مراجع مُحايد + خبير المجال | موافقة + توقيع | 48 ساعة |
| **البناء** | CI/CD | تحديث `skills_index` + evals | تلقائي |
| **النشر** | SRE | تفعيل تدريجي 10% → 100% | 24 ساعة |
| **المراقبة** | فريق Platform | لوحات: استخدام، أخطاء، زمن | مستمرة |
| **الإهمال** | المالك الأصلي | استبدال بـ Skill بديلة أو حذف | — |

### 6.2 مِحو الأمان عند الإهمال

- نقل المهارة إلى `archive/skills/<name>/<version>/`.
- إبقاء الإصدار القديم قابلاً للاسترجاع لمدة 90 يومًا.
- حذف أي `tenant_scope: tenant` يحتوي بيانات حساسة خلال 30 يومًا.

## 7. القيود والمعايير

| القيد | التفصيل | التحقق |
|---|---|---|
| **ميزانية الريبو** | إجمالي رموز جميع Skills النشطة ≤ 50,000 رمز | فحص آلي في CI |
| **ميزانية الجلسة** | لا تتجاوز Skills المحمَّلة 8,000 رمز في المهمة الواحدة | عداد في `Skill Usage Log` |
| **حدّ التحميلات** | ≤ 5 مهارات لكل مهمة | `enforceBudgetAndDeps` |
| **التوافق** | كل Skill تعمل على كلٍّ من `gemini-3.5-flash-lite` و`gemini-3.6-flash` | evals متعددة النماذج |
| **الاختبار** | كل Skill مرفق بـ ≥ 3 اختبارات (deterministic + eval rubric) | CI gate |
| **المراجعة** | مراجعة بشرية إلزامية كل 90 يومًا | تنبيه آلي قبل الانتهاء |
