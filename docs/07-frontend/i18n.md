# التدويل والتعريب (i18n)

نظام التدويل في OmniRAG مبني داخلياً بالكامل (لا اعتماد على `react-i18next` أو `next-intl`). يعتمد على قواميسَين قويَّي التنميط مع استرجاع آمن للقيم الافتراضية، ويُطبَّق على HTML قبل أول بايت لمنع وميض الاتجاه/اللغة.

## الملفات

| الملف                                    | الدور                                                                             |
| ---------------------------------------- | --------------------------------------------------------------------------------- |
| `src/lib/i18n/index.ts`                  | مخرِج `t(locale, key, params?)`، أنواع `Locale`/`Dictionary`، `SUPPORTED_LOCALES` |
| `src/lib/i18n/dictionaries/en.ts`        | قاموس الإنجليزية (مرجع الشكل TypeScript)                                          |
| `src/lib/i18n/dictionaries/ar.ts`        | قاموس العربية (1203 سطر، مكتوب ضد شكل `en.ts`)                                    |
| `src/lib/preferences/userPreferences.ts` | مخزن التفضيلات (theme, font, density, math, language)                             |

## اللغات المدعومة

`SUPPORTED_LOCALES = ['ar', 'en'] as const` — العربية هي اللغة الافتراضية.

```ts
export function isLocale(value: unknown): value is Locale {
  return value === 'ar' || value === 'en';
}
```

## توقيع `t`

```ts
import { t, isLocale, getDictionary, SUPPORTED_LOCALES } from '@/lib/i18n';

export type Locale = 'ar' | 'en';
export type Dictionary = typeof en;

t(locale: Locale, key: string, params?: Record<string, string | number>): string;
```

### قواعد الاسترجاع

1. يبحث في `dictionaries[locale]`، ثم في القاموس الإنجليزي كـ fallback، ثم في الـ key نفسه (لتفادي ظهور حقول فارغة في التطوير).
2. يدعم استبدال `{placeholder}` عبر `value.replace(/\{(\w+)\}/g, ...)`.
3. الاستبدال يحترم نوع الـ param (`string | number`).

### مثال

```ts
t(lang, 'chat.citationIndex', { index: 3 });
// ar → '[3]'
// en → '[3]'

t(lang, 'kb.docsIndexed', { indexed: 12, total: 50 });
// ar → '12 / 50'
```

## كيف تُحقن اللغة في الـ HTML الأولي

`src/app/layout.tsx` (جذر RootLayout):

1. يقرأ الـ `cookie` `omnirag_lang` و`omnirag_theme` من `headers()`.
2. يُولِّد `<html lang={lang} dir={lang === 'ar' ? 'rtl' : 'ltr'} className={theme === 'dark' ? 'dark' : ''}>`.
3. يحقن خطوط `IBM_Plex_Sans_Arabic` و`Cairo` و`Tajawal` و`Amiri` عبر `next/font/google` كمتغيرات CSS (`--font-ibm-plex-sans-arabic`، `--font-cairo-next`، `--font-tajawal-next`، `--font-amiri-next`).

النتيجة: لا وميض لاتجاه/مظهر على أول بايت HTML.

## تبديل اللغة

### في الواجهة

- `Header` يعرض زرين `العربية` / `English` في القائمة المنسدلة.
- `AuthScreen` يعرض زر `Globe` يبدّل اللغة ويعيد تهيئة `lang` prop.
- `LandingPage` يمرّر `setLang` و`lang` عبر props.

### في كل مكان آخر

- `src/app/(workspace)/chat/page.tsx` و`knowledge/page.tsx` و`mcp/page.tsx` و`analytics/page.tsx` و`settings/page.tsx` و`auth/page.tsx` تقرأ `lang` من `useUserPreferences()` (عبر `WorkspaceShell`) ثم تمرّرها prop إلى المكوّن الرئيسي.
- `WorkspaceShell` يكتب `lang` على الـ `<main>` كـ `dir={lang === 'ar' ? 'rtl' : 'ltr'}`.

### الاستمرارية

`useUserPreferences().update({ language })` يكتب في localStorage + cookie عبر `document.cookie = 'omnirag_lang=...'`، فيقرأ الـ layout الجديد القيمة فوراً (لكن التأثير الفعلي يُلاحَظ في الـ navigation التالي، ليس في نفس الصفحة — هذا قيد Next.js).

## اتجاه RTL

### على مستوى المكونات

كل مكوّن يقرأ `lang === 'ar'` ويُمرّر `dir` صراحةً إلى الـ containers. على سبيل المثال في `ChatStudio`:

```tsx
<div className="print-expand flex h-full w-full overflow-hidden bg-white" dir={lang === 'ar' ? 'rtl' : 'ltr'}>
```

`Header` يستخدم `document.dir === 'rtl'` لتعكس منطق `ArrowLeft/ArrowRight` داخل `role="tablist"` (تنقل بصري يبدأ من اليمين في العربية).

### الأيقونات التي تحتاج قلب

بعض الأيقونات يجب عكسها بصرياً في RTL:

```tsx
<Send className={`w-3.5 h-3.5 ${lang === 'ar' ? 'rtl:-scale-x-100' : ''}`} />
<PanelLeftClose className={`w-4 h-4 text-slate-500 ${isRtl ? 'rtl:-scale-x-100' : ''}`} />
<ArrowUpLeft className={`w-3 h-3 text-indigo-400 ... ${lang === 'ar' ? 'rtl:-scale-x-100' : ''}`} />
```

### منطق الـ flex والـ inset

- تُستخدم خصائص `start/end` بدلاً من `left/right` كلما أمكن.
- `QuestionNavigator` يستخدم `style={{ insetInlineEnd: '0.375rem' }}` لوضع نفسه على الحافة المناسبة تلقائياً في RTL/LTR.
- `ChatSidebar` يضع شريط التظليل على `right:0` في RTL و`left:0` في LTR.
- `Header` يضع القائمة المنسدلة `left-0` في RTL و`right-0` في LTR.

## النصوص العربية في الـ math (katex4arabic)

`SettingsView` يستعمل `renderArabicToString` من مكتبة `katex4arabic` لمعاينة الرياضيات. هذه ميزة اختيارية للمستخدم:

- مفعّلة عبر `mathMode: 'arabic'` في `useUserPreferences()` (افتراضي `katex`).
- `MathPreview` يعرض ثلاث معادلات LaTeX نموذجية باستخدام الوضع المختار.
- خيار `mathArabicNumerals` يبدّل بين الأرقام العربية (`arabic`) والأرقام اللاتينية (`latin`).

`RichMessageRenderer` يستخدم `rehypeKatex` (محول KaTeX قياسي لـ remark-math) افتراضياً، وملحق داخلي `rehypeKatexArabic` لمعالجة الحالات الشائعة.

## ملخص القواعد

1. لا تضع نصوصاً عربية/إنجليزية مباشرة في JSX — استخدم دائماً `t(lang, 'namespace.key', params)`.
2. إذا أضفت مفتاحاً جديداً إلى `en.ts`، يجب إضافته إلى `ar.ts` أيضاً (خطأ compile إن لم تفعل).
3. عند الحاجة لمتغير في النص، استخدم `{name}` وأضفه في `params`.
4. في المكونات الجديدة، اقرأ `lang` من `useUserPreferences()` (داخل `(workspace)`) أو اقبلها كـ prop (مثل `LandingPage`, `AuthScreen`).
5. اضبط `dir={lang === 'ar' ? 'rtl' : 'ltr'}` على الـ containers الرئيسية.
6. عند استبدال `alert()` أو نص مكتوب يدوياً، ابحث أولاً في القاموس — قد يكون المفتاح موجوداً.
