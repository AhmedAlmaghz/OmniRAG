# ملف التسويق للنظام — OmniRAG Product Marketing Playbook

هذا الملف هو مرجع تسويق OmniRAG العملي: التموضع، الرسائل، الشخصيات، نقاط البيع الفريدة، الإطار التنافسي، وأسس التواصل في كل قناة. جميع المزاعم مبنية على قدرات موثّقة فعلياً.

---

## 1. بيان التموضع (Positioning Statement)

> **للشركات والمؤسسات** التي تحتاج بنياناً معرفياً داخلياً يجيب بالعربية والإنجليزية بدقة وبراهين، **OmniRAG** هي FromScratch Platform لـ RAG مؤسسية متعددة المستأجرين: تجمع بين بحث هجين (Vector + BM25) ودمج RRF وفحص حقن وSSRF/PII عبر درع متكامل، وتعمل فوراً على Vercel أو Docker أو أي خادم — **بدون مغامرات vendor lock-in ولا أدوات مفككة**.

### التموضع في سياق الفئة

| المحور                                              | موقف OmniRAG                                                                                   |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **vs نقاط الانطلاق RAG البسيطة** (RAG-as-a-feature) | نظام كامل متعدد المستأجرين، مع إدارة مفاتيح API، فرق SSO، فوترة/خطط، OCR، موصلات حية، MCP gate |
| **vs المنصات الضخمة المحتكرة**                      | Open، deployable anywhere، schema ملكك، لا lock-in، تكلفة شفافية                               |
| **vs الحلول الأمريكية الأقوى في الإنجليزية**        | تفوّق عربي: تطبيع عربي، GIN عربي، RTL، KaTeX عربي، دردشة عبر أداة عربية النواة                 |

## 2. الشخصيات المستهدفة (Personas)

### شخصية أ: مدير التقنية / CTO (الراعي المالي)

- **الألم:** يريد RAG جاهزاً للإنتاج بلا تراكم فرق متخصصة؛ يرفض المنصات المغلقة (vendor lock-in) والاشتراكات المتضخمة.
- **ما نبيعه له:** نشر بسطر أوامر واحد — صورة Docker تتضمن التطبيق + PostgreSQL + Qdrant، وحواجز أمنية مسبقة البناء (SSRF/injection/PII)، وقاعدة بيانات بمخطط مملوك له كلياً.
- **رسائل مفتاحية:** «انشر خلال 10 دقائق» — «مخطط بياناتك مملوك لك» — «العزل بين المستأجرين في الجدول نفسه».

### شخصية ب: مهندس AI / Backend (صاحب القرار التقني)

- **الألم:** يعرف أن RAG ليس «نموذج + متجه» — يحتاج تقوية استرجاع، تقييم، إعادة ترتيب، تغطية كاملة للمستند الطويل، وربط بمفاتيح وصلاحيات.
- **ما نبيعه له:** Retrieval هندسي متعدد الطبقات: RRF، كاشف Aggregative، حراسة تقادم المتجهات، إعادة تضمين إجبارية عند تغيير النموذج، وإعادة فهرسة المستندات — محرك فعلي يستخدمه يومياً.
- **رسائل مفتاحية:** «RRF حقيقي لا تجريبي» — «دمج vector + lexical فعلي لا اختيار يدوي» — «تفحص صحة المنصة بنفسك عبر `/api/v1/diagnostics`».

### شخصية ج: مدراء المعرفة والامتثال (Knowledge / Compliance Managers)

- **الألم:** يريدون إجابات قابلة للاستشهاد، بلا تسريب بيانات، وبأدوار دقيقة — المنافسون يتركون الأمن «للمستخدم».
- **ما نبيعه له:** عزل tenant صارم، PII redaction في التدفق، تشفير أسرار (AES-GCM)، تتبع تدقيقي، موافقة على الأدوات مع آثار جانبية — جاهزية امتثال دون شهادات خارجية.
- **رسائل مفتاحية:** «إجابة بمرجع صفحة حرفياً» — «الوصول بمحتوى مسند لأدوار» — «الأحداث الأمنية في جدول audit_logs».

### شخصية د: الوكالات ومزودو حلول (Agencies/MSPs)

- **الألم:** يخدمون عشرات العملاء ولا يستطيعون بناء RAG لكل عميل من الصفر.
- **ما نبيعه له:** Multi-tenancy أصيلة (كل عميل tenant منعزل مع مفاتيحه ونماذجه)، إعدادات لكل tenant، وخطط قابلة للتخصيص.
- **رسائل مفتاحية:** «أدر كل عملائك من مثيل واحد» — «كل مستأجر في مساحته المعزولة الخاصة».

## 3. نقاط البيع الفريدة (Unique Selling Propositions)

| USP                                | الدليل من الكود                                                         | الرسالة التسويقية                  |
| ---------------------------------- | ----------------------------------------------------------------------- | ---------------------------------- |
| **بحث هجين حقيقي RRF**             | RRF بأوزان وk مزمنان في `src/lib/chat/stream`                           | «دقة تتفوق على البحث المتجهي وحده» |
| **أمان مسبق البناء (Not bolt-on)** | SSRF + Injection Shield + PII + Argon2id + AES-256-GCM                  | «لا أمن إضافي بعد الشراء»          |
| **عربي من الدرجة الأولى**          | GIN عربي+إنجليزي، تطبيع عربي، RTL، KaTeX عربي، chat models تدعم العربية | «أفضل RAG للعربية في السوق»        |
| **Multi-tenancy ابتدائي**          | `tenantId` في كل جدول + مفاتيح API منفصلة                               | «بطاقة عميل = حاوية ملكية»         |
| **Deploy Anywhere**                | Vercel + Docker -> أي VPS/Kubernetes                                    | «حرية البنية التحتية»              |
| **وكابالية MCP كاملة**             | سيرفرات MCP خارجية/داخلية، OAuth مشفر، توليد أدوات، بحث حي              | «من RAG إلى Agents حقيقية»         |
| **استشهادات صريحة**                | لوحة citations، named-document coverage                                 | «كل إجابة بجذورها»                 |
| **قابلية تشغيل كاملة**             | /api/health، فحوص تشخيص حقيقية، 12 hook، 41 ملف docs                    | «يوماً-بعد-يوم، وليس منصة تجريبية» |

## 4. هيكل الرسائل (Messaging Architecture)

### شعار المنصات (الأساس)

> **«OmniRAG — معرفتك مؤسسة، إجاباتك براهين، وتقنيتك ملكية»**

### الركائز الثلاث (Message Pillars)

1. **الدقة القابلة للإثبات (Trusted Answers)**
   - بحث هجين + RRF، استشهادات بصفحات، تغطية كاملة للمستندات، تطبيع عربي.

2. **الأمان المؤسسي (Built-in Security)**
   - حقن SSRF، فحص الحقن، PII، Argon2id، AES-GCM، audit_logs، roles.

3. **ملكية وانتشار (Own & Deploy)**
   - Codebase كاملة قابلة للمراجعة، لا black-box — تعمل على Docker/Vercel/خادمك، بدون احتكار مفاتيح خارجية.

### نبرة التواصل

- **احترافية تقنية أصيلة** — لا مبتذلة، لا مزعومة بالإمكانيات.
- **عربية فصحى دقيقة مع عناصر إنجليزية** في سياق عاديات التقنية وهوية العلامة.
- **تفعيلية:** verb-first («ابنِ»، «انشر»، «تحكم»، «وثّق»).

## 6. بيانات التمايز التنافسي (Leapfrog Framing)

- **تخلّص من "المداس"**: معظم أنماط RAG النموذجية (chat-with-docs) مجرد أمثلة؛ OmniRAG منصة تشغيل يومية بجدولة ومكانات صلاحيات وتحليلات استخدام وصحّتين.
- **حماية من "الفوضى"**: من جدار النيران إلى audit_logs — كل مخاطرة في teammate script يُختم ويُبلغ.
- **"عربي في حمضه النووي"**: معظم ما يتنافس على العربية ترجمة تسويقية؛ OmniRAG لديه normalizers وindexes و i18n كاملة لا ملصق "يدعم العربية".

---

## 7. الاستخدامات المؤسسية المتاجهة (Vertical Use-Cases)

- **المكتبات القانونية:** استرجاع العقود واللوائح باستشهادات فقرات.
- **الرعاية الصحية:** بروتوكولات وسياسات داخلية (مع ضمان SSO وPII).
- **التعليم والجامعات:** مستودع مراجع جامعي مع مفاتيح API لكل مدرسة.
- **الدعم الفني:** قاعدة معرفة داخلية للمساندي (مزوّدة بالتصدير ووكلاء).
- **السيادة الصحفية:** أرشيف قابل للبحث من connected sources (RSS، المواقع) مع تحديث تلقائي.

> كل حالة استخدام قابلة للإثبات الآن عبر الـ docs ولا تتطلب تطويراً إضافياً لبدء العمل.

---

## 8. التحقق من النزاهة التسويقية (Claims Governance)

للحفاظ على ثقة السوق، يلتزم فريق التسويق بالقواعد التالية:

- ❌ لا «أفضل منصة AI في العالم».
- ❌ لا «100% آمن».
- ❌ لا نادرج خصائص "قريباً" في مواد الإطلاق (بل نضعها في قسم Roadmap واضح).
- ✅ فقط عبارات أمينة مثل: "بنيت على كود قابل للمراجعة" و "اختبارات تغطي حواجز الأمان الرئيسية".
- ✅ كل claim تم اعتماده يجب أن يرتبط بصفحة في `docs/` أو ملف في الكود.
