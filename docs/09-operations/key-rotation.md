# دليل تدوير مفاتيح التشفير (Key Rotation Runbook)

يغطي هذا الدليل تدوير **`MCP_OAUTH_ENCRYPTION_KEY`** — مفتاح AES-256-GCM الذي يشفّر أثناء السكون (at rest): رموز OAuth لسيرفرات MCP، واعتمادات مزوّدي الذكاء الاصطناعي (`provider_credentials`)، وأسرار الـ webhooks.

> **متى تدوّر؟** (1) عند الاشتباه بتسرب المفتاح، (2) عند مغادرة أي شخص كان يملكه الفريق، (3) دورياً وفق سياسة المؤسسة (توصية عامة: كل 12 شهراً)، (4) **فوراً** إن وجدت المفتاح في أي ملف مُرسل لمستودع — كما حدث مع القيمة التي أُزيلت من `.env.example` في v0.12.8: مفتاح دخل تاريخ git يُعدّ مكشوفاً ويجب تدويره.

## ماذا يحدث عند التدوير (تأثير تشغيلي — اقرأه قبل التنفيذ)

التشفير بمفتاح وحيد بلا تدوير مفتاح-على-مفتاح (key-wrapping)، لذا **كل النصوص المشفّرة بالمفتاح القديم تصبح غير قابلة للفك** لحظة تبديل المفتاح:

| الأثر | الوصف | الإجراء المطلوب |
| --- | --- | --- |
| سيرفرات MCP OAuth | رموز الوصول/التحديث المخزّنة تفشل في فك التشفير | إعادة ربط (re-connect) كل سيرفرات MCP من واجهة MCP Gateway لكل مستأجر |
| اعتمادات المزوّدين | مفاتيح مزوّدي AI المخزّنة في الإعدادات تفشل | إعادة إدخال مفاتيح المزوّدين من شاشة Settings → Providers لكل مستأجر |
| أسرار Webhooks | توقيعات التحقق تنكسر | إعادة توليد السر في إعدادات كل webhook endpoint |

لا تُفقد أي بيانات مستندات/محادثات — الأثر محصور في الاعتمادات المشفّرة فقط، والفشل عند الفك يظهر كخطأ صريح (التطبيق يرفض التشفير بمفتاح غائب في الإنتاج أصلاً — راجع `src/lib/mcp/auth/encryption.ts`).

## خطوات التنفيذ (نافذة صيانة قصيرة)

1. **ولّد مفتاحاً جديداً:**
   ```bash
   openssl rand -base64 32
   ```
2. **حدّث البيئة:** ضع المفتاح الجديد في `MCP_OAUTH_ENCRYPTION_KEY` في Vercel (Project → Settings → Environment Variables) أو في `.env`/compose البيئة الذاتية الاستضافة — لكل البيئات (production/preview).
3. **أعد النشر** حتى يلتقط الـ runtime المفتاح الجديد.
4. **أعد ربط الاعتمادات:** لكل مستأجر — أعد اتصال سيرفرات MCP، وأعد إدخال مفاتيح المزوّدين، وأعد توليد أسرار webhooks.
5. **أبطل المفتاح القديم نهائياً:** احذفه من كل مخازن البيئة (Vercel/GitHub Secrets/CI/مدير كلمات مرور الفريق). مفتاح ما زال في أي مخزن = التدوير لم يكتمل.
6. **تحقق:** نفّذ استدعاء MCP حياً من المحادثة (مثلاً `web_live_search`)، وتأكد أن `provider credentials` تُستخدم بنجاح في مسار توليد واحد.

## ما لا يغطيه هذا الدليل (ملاحظة معمارية)

- `DATABASE_URL` و`GEMINI_API_KEY` ومفاتيح التخزين تُدار من مزوّديها وتُدوَّر وفق توثيقهم المباشر — هذا الدليل خاص بمفتاح التشفير الداخلي فقط.
- تحسين مستقبلي مخطط: مغلف تشفير بمفتاحَين (old + new) يتيح تدويراً بلا انقطاع عبر إعادة تشفير تدريجي في الخلفية — راجع خارطة الطريق في `SDLC/08-roadmap/`.
