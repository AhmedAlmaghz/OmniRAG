# 🚀 منصة OmniRAG (الإصدار v0.12.8)

**OmniRAG** هي منصة متكاملة ومتقدمة للجيل الجديد من أنظمة **الاسترجاع المعزز بالتوليد (RAG)** الموثوقة والمخصصة للمؤسسات متعددة المستأجرين (Multi-Tenant Enterprise RAG & MCP Agentic Engine).

---

## 🔐 متغيرات البيئة الإلزامية في الإنتاج (Mandatory Production Env)

> التطبيق **يرفض العمل** في الإنتاج (`NODE_ENV=production`) بدون المتغيرات التالية:

| المتغير                             | الغرض                                                                                           |
| ----------------------------------- | ----------------------------------------------------------------------------------------------- |
| `DATABASE_URL` أو `POSTGRES_URL`    | قاعدة بيانات PostgreSQL (Neon/Supabase أو أي مزوّد)                                             |
| `MCP_OAUTH_ENCRYPTION_KEY`          | مفتاح AES-256-GCM لتشفير اعتمادات الموصلات وأسرار Webhooks — ولّده بـ `openssl rand -base64 32` |
| `CRON_SECRET` أو `JOBS_TICK_SECRET` | حماية مسار `/api/v1/jobs/tick` (Vercel Cron) — بدونه يرد 401                                    |

متغيرات اختيارية مهمة: `PLAN_SELF_SERVE=true` يسمح بالترقية الذاتية بين الخطط (مقفلة افتراضيًا إلى إدخال مزود فواتير)، `ALLOWED_ORIGINS` لقائمة CORS المسموحة، `ALLOW_CLIENT_ENV` لقبول متغيرات من الواجهة (غير موصى به في الإنتاج).

## 🌟 أبرز الميزات والقدرات الرئيسية

### 1. 💬 استوديو المحادثة المعززة وحفظ الجلسات (Durable PostgreSQL Chat Persistence)

- **حفظ المحادثات دائمياً:** يتم حفظ كافّة الجلسات والرسائل تلقائياً في قاعدة بيانات **PostgreSQL** بصورة معزولة لكل مستأجر (`tenantId`).
- **إدارة الجلسات السابقة:** إمكانية التبديل بين جلسات المحادثة، تعديل عناوينها، أو حذفها بمرونة.
- **توليد عناوين ذكية:** تحديث عنوان المحادثة تلقائياً بناءً على سياق الاستفسار الأول للمستخدم.

### 2. 📚 تحديد وتحديث مصادر المعرفة المخصصة (Knowledge Collections & Sources Scoping)

- **فلترة نطاق الاستعلام:** إمكانية تخصيص وتحديد مجموعات ومصادر معرفية معينة للبحث فيها أثناء جلسة المحادثة، أو اختيار الاستعلام الشامل لكافة المصادر المتاحة للمستأجر.
- **ربط المصادر بالجلسة:** حفظ التفضيلات المحددة للمصادر ضمن كائن الجلسة في قاعدة بيانات PostgreSQL.
- **موصلات مزامنة حية (Live Sync):** خطوط استخلاص فعلية تعمل من الخادم لكلٍّ من: صفحات الويب/المقالات (`url`)، تغذيات RSS/Atom (`rss` — آخر 30 عنصراً)، مستودعات GitHub العامة أو الخاصة عبر PAT (`github`، README + البيانات الوصفية)، تفريغ يوتيوب الحقيقي (`youtube`)، وملفات PDF عبر خط OCR متعدد المحركات (`file`). كل الطلبات الصادرة تمر عبر حرس SSRF (قائمة نطاقات خاصة محظورة + مهلة + سقف حجم). الموصلات التي تتطلب OAuth (gdrive/notion/confluence/slack/email/database/api) موسومة "قريباً" وتفشل بصدق بدل فهرسة محتوى وهمي.

### 3. 🔍 محرك استرجاع هجين فائق الدقة (Hybrid RRF Retrieval)

- **دمج متقدم:** يدمج بين البحث المتجهي الكثيف (Dense Vector Embeddings) والبحث المعجمي (BM25 Lexical) باستخدام خوارزمية **Reciprocal Rank Fusion (RRF)**.
- **دعم الاستشهاد بالمرجع (Citations):** استخراج دقيق للمصادر والصفحات المرجعية واستعراضها بجانب الإجابات المستوردة من نماذج Gemini.

### 4. 🛡️ درع الأمن والحماية والتحقق من الحقن (Security Guardrails & Injection Shield)

- **منع هجمات الحقن:** فحص واستكشاف محاولات Prompt Injection واختراق السياق حتمياً قبل إرسال الطلب للنموذج.
- **مركز أمن المستأجرين:** مراقبة وتحليل سجلات الوصول والأحداث في الوقت الفعلي.

### 5. 🔌 بوابات بروتوكول سياق النموذج (MCP Gateways)

- **تكامل أدوات MCP:** الاتصال بسيرفرات MCP الخارجية والداخلية لاستدعاء الوظائف (Function Calling) مع آلية موافقة المستخدم وتوثيق تنفيذ الأدوات.

### 6. 📄 استوديو معالجة واستيراد المستندات (Document Ingestion Studio)

- **دعم صيغ متعددة:** معالجة مستندات PDF, DOCX, TXT, JSON, CSV.
- **تجزئة ذكية (Chunking):** تقطيع المستندات وتوليد التضمينات المتجهية وإسنادها للمجموعات المعرفية للمستأجر.

## 🛠️ التقنيات المستخدمة (Tech Stack)

- **الإطار البرمجي:** Next.js 16.3 (App Router، مسارات متعددة `/chat`, `/knowledge`, `/mcp`, `/analytics`, `/settings`) & React 19.2
- **لغة البرمجة:** TypeScript
- **التنسيق والواجهات:** Tailwind CSS v4 & Lucide Icons
- **قاعدة البيانات والتخزين الدائم:** PostgreSQL (Drizzle ORM) & Qdrant للبحث المتجهي
- **الذكاء الاصطناعي والتضمين:** Google Gemini SDK (`@google/genai`) - نموذج `gemini-3.7-flash`

## ⚙️ التشغيل المحلي (Run Locally)

### المتطلبات الأساسية

- **Node.js** (النسخة 18 أو أحدث)
- **npm** أو **bun**

### خطوات التشغيل

1. **تثبيت الحزم والاعتمادات:**

   ```bash
   npm install
   ```

2. **إعداد متغيرات البيئة:**
   أنشئ ملف `.env.local` واضبط المفاتيح المطلوبة (نموذج المصادقة محلي ويستخدم PostgreSQL لتخزين الحسابات والجلسات — راجع `.env.example`):

   ```env
   GEMINI_API_KEY=your_gemini_api_key_here
   DATABASE_URL=postgresql://username:password@localhost:5432/omnirag
   ```

3. **تشغيل خادم التطوير:**
   ```bash
   npm run dev
   ```
   افتح [http://localhost:3000](http://localhost:3000) في المتصفح لاستعراض المنصة.

## 🐳 التشغيل عبر Docker (أي مزود استضافة)

التطبيق جاهز للعمل كحاوية Docker على أي بيئة (Cloud Run، Fly.io، Railway، Render، ECS، Kubernetes، أو خادم خاص). الصورة تعتمد Node 24، تستمع على `0.0.0.0` وعلى المنفذ من متغير البيئة `PORT` (الافتراضي 3000)، وتفحص الجاهزية عبر `/api/health`.

### بناء وتشغيل الحاوية يدوياً

```bash
# البناء
docker build -t omnirag .

# التشغيل — مرّر متغيرات البيئة عبر --env-file أو -e
docker run -d --name omnirag \
  -p 3000:3000 \
  --env-file .env \
  omnirag
```

> **مهم:** لا تُدمج قيم `.env` داخل الصورة أبداً (ملف `.dockerignore` يستبعدها) — تُمرَّر في وقت التشغيل فقط. المتغير الوحيد الذي يقرأ وقت البناء هو `APP_URL` إن احتجت قيمة افتراضية.

### تشغيل المجموعة كاملة (تطبيق + PostgreSQL + Qdrant)

```bash
cp .env.example .env   # ثم عدّل المفاتيح (GEMINI_API_KEY مطلوب)
docker compose up -d --build
```

يعمل التطبيق على `http://localhost:3000` مع قاعدة بيانات ومحرك بحث متجهي داخليين (بيانات دائمة في أحجام Docker). `DATABASE_URL` و`QDRANT_URL` تُعيَّن تلقائياً للخدمات الداخلية وتتجاوز أي قيم في `.env`.

بعد أول تشغيل، أنشئ جداول قاعدة البيانات. مصدر الحقيقة الوحيد للمخطط هو `src/db/schema.ts`، وكل التهجيرات دُمجت في ملف baseline واحد (`drizzle/0000_baseline_unified.sql`):

```bash
# الطريقة 1 — تطبيق المخطط مباشرة من schema.ts (الأبسط للتطوير)
DATABASE_URL=postgresql://omnirag:omnirag@localhost:5432/omnirag npm run db:push

# الطريقة 2 — التهجير اليدوي عبر سكريبت SQL موحد (idempotent — آمن الإعادة)
# يعمل على قاعدة جديدة أو قاعدة موجودة من نسخة سابقة، ولا يحذف أياً من بياناتك
DATABASE_URL=postgresql://omnirag:omnirag@localhost:5432/omnirag npm run db:migrate:manual
```

`scripts/manual-migration.sql` يغطي الـ 25 جدولاً كاملةً (بما فيها فهارس البحث النصي العربية/الإنجليزية GIN وجداول التشغيل `rate_limit_windows` و`usage_counters`)، ويستثني عمداً جداول `pgboss` (ينشئها pg-boss عند الإقلاع) وجداول pgvector الديناميكية (`vector_chunks*` — ينشئها المحوّل حسب بُعد التضمين). عند تعديل `schema.ts`، ولّد تهجيراً جديداً بـ `npm run db:generate` وأبقِ السكريبت اليدوي متزامناً معه.

> **ملاحظة:** التطبيق ينشئ المخطط ويزرع البيانات الأولية تلقائياً عند الإقلاع أيضاً (`migrateAndSeedWithDrizzle`) — السكريبت اليدوي للنشر المسبق أو إصلاح قاعدة موجودة.

### ملاحظات النشر على المزودين

- **المنفذ:** أي مزود يمرر `PORT` ستستخدمه الحاوية تلقائياً — لا حاجة لأي تعديل.
- **نماذج OCR:** ملفات `ara/eng.traineddata` تُدمج داخل الصورة (تُنسخ من مجلد المشروع إن وُجدت، أو تُحمَّل وقت البناء)، فلا يحتاج OCR المحلي أي اتصال بالإنترنت وقت التشغيل.
- **الحد الأدنى من المتغيرات:** `GEMINI_API_KEY` و`DATABASE_URL` و`QDRANT_URL`؛ بقية المفاتيح (Mistral، Groq، Unstructured، S3…) اختيارية وتفعّل قدرات إضافية.
- **الحالة:** الحاوية عديمة الحالة (stateless) ويمكن توسيعها أفقياً — الرفع الكبير للملفات يذهب مباشرة إلى S3/Blob من المتصفح.
