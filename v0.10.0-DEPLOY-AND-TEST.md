# دليل النشر والتجريب — OmniRAG v0.10.0 (المراحل 0–7)

> الفرع `dev-pro` (التاج `v0.10.0`) يحتوي 8 التزامات، واحد لكل مرحلة.
> هذا الدليل يشرح ما تغيّر مما يؤثر على النشر، وكيف تُنشر على البيئتين
> (Docker self-hosted + Vercel)، وخطة تجريب كل مرحلة يدويًا.

## 2) متغيرات البيئة

### إلزامية في الإنتاج

| المتغير                             | الغرض                                                                           |
| ----------------------------------- | ------------------------------------------------------------------------------- |
| `DATABASE_URL` أو `POSTGRES_URL`    | Postgres 17 — التخزين، الطوابير، pgvector                                       |
| `MCP_OAUTH_ENCRYPTION_KEY`          | AES-256-GCM لتشفير اعتمادات المزودين/الموصلات/OAuth/webhook secrets عند التخزين |
| `APP_URL`                           | الروابط الذاتية + callbacks (OAuth/SSO)                                         |
| `ALLOWED_ORIGINS`                   | CORS — قائمة مفصولة بفواصل                                                      |
| `CRON_SECRET` أو `JOBS_TICK_SECRET` | حماية `/api/v1/jobs/tick` (Vercel) — يُرفض الطلب في الإنتاج بدونه               |

### اختيارية حسب الميزة (تدهور صادق عند غيابها)

| المتغير                                                                                                           | الميزة                                                                            |
| ----------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `GEMINI_API_KEY` / `GOOGLE_GENERATIVE_AI_API_KEY`                                                                 | مزود Google (الافتراضي التاريخي)                                                  |
| `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GROQ_API_KEY`, `MISTRAL_API_KEY`, `OLLAMA_BASE_URL`, `OPENROUTER_API_KEY` | مزودو المرحلة 1 (يمكن إدخالها أيضًا من واجهة «المزودون» لكل مستأجر — مشفرة في DB) |
| `QDRANT_URL` + `QDRANT_API_KEY`                                                                                   | مخزن المتجهات Qdrant (بدونه يمكن اختيار pgvector من الإعدادات)                    |
| `S3_*` / `BLOB_READ_WRITE_TOKEN`                                                                                  | مخزن الكائنات S3/Vercel Blob (الأرشيف الدائم للملفات الأصلية)                     |
| `MISTRAL_API_KEY`, `UNSTRUCTURED_API_KEY`+`UNSTRUCTURED_API_URL`, `GROQ_API_KEY`                                  | محركات الاستخراج (OCR/تحويل/تفريغ صوتي)                                           |
| `TAVILY_API_KEY` / `SERPER_API_KEY` / `BRAVE_API_KEY`                                                             | البحث الحي في MCP                                                                 |
| `SLACK_BOT_TOKEN`, `GITHUB_TOKEN`                                                                                 | تكاملات Slack/GitHub الحقيقية في الدردشة                                          |
| `SMTP_HOST/PORT/USER/PASS/SECURE/FROM` أو `RESEND_API_KEY`                                                        | مهارة إرسال البريد                                                                |
| `ALLOW_CLIENT_ENV=false`                                                                                          | افتراضيًا مرفوض في الإنتاج — لا تفعّله إلا للضرورة                                |
| `ENABLE_JOB_WORKER=false`                                                                                         | لإيقاف عامل الطوابير في حاوية معينة (عقد متعددة)                                  |
| `ARCHIVE_UPLOADS=true`                                                                                            | أرشفة الملفات الأصلية في مخزن الكائنات (opt-in لاعتبارات PII)                     |

> إعدادات OIDC (SSO) لا تُوضع في البيئة بل لكل مستأجر من واجهة
> «SSO» في الإعدادات (issuer + clientId + secret مشفر).

## 3) النشر على Docker (self-hosted)

```bash
git checkout v0.10.0          # أو dev-pro
docker compose build --no-cache
# أضف المتغيرات الإلزامية في .env (أهمها MCP_OAUTH_ENCRYPTION_KEY وDATABASE_URL)
docker compose up -d
docker compose logs -f app    # راقب سطر: Background connector-sync worker active
```

- `docker-compose.yml` يرفع: app + postgres:17 + qdrant.
- عامل pg-boss يعمل داخل عملية التطبيق عبر `instrumentation.ts`
  (يُعاد توافق الجداول المجدولة كل 5 دقائق تلقائيًا).
- فحص الصحة موجود في Dockerfile على `/api/health`.
- نقل stdio لخوادم MCP المحلية **مسموح هنا فقط** (البوابة: غياب `VERCEL`).

## 4) النشر على Vercel

1. اربط المستودع (فرع `dev-pro` أو بعد دمجه في `main`) — الإصدار 0.10.0.
2. أضف المتغيرات الإلزامية في لوحة المشروع
   (`MCP_OAUTH_ENCRYPTION_KEY` أولًا — بدونه تفشل أي عملية تشفير اعتمادات).
3. `vercel.json` يفعّل cron `/api/v1/jobs/tick` كل 5 دقائق تلقائيًا؛
   أضف `CRON_SECRET` وامنح Vercel Cron نفس القيمة في الترويسة.
4. تخزين الكائنات المحلي **زائل** على Vercel — فعّل S3 أو Vercel Blob
   إن أردت أرشيفًا دائمًا (`ARCHIVE_UPLOADS`).
5. stdio معطّل تلقائيًا (بوابة `process.env.VERCEL`) — خوادم MCP المحلية
   لا تظهر إلا في النشر الذاتي.

## 5) قائمة تحقق ما بعد النشر

- [ ] `/api/health` يعيد 200.
- [ ] سجلات الإقلاع تظهر `Background connector-sync worker active` (Docker).
- [ ] الواجهة تفتح بالعربية افتراضيًا، والتبديل إلى الإنجليزية يعمل ويُحفظ.
- [ ] نافذة البيئة عند أول إطلاق تظهر درجة الجاهزية (Postgres/Qdrant/Mistral).
- [ ] إنشاء مفتاح API من الإعدادات → المفتاح يظهر **مرة واحدة** ثم يختفي.
- [ ] `/api/docs` يعرض وثائق OpenAPI.
- [ ] لا أخطاء `MCP_OAUTH_ENCRYPTION_KEY must be set in production` في السجلات.

## 6) خطة التجريب اليدوي لكل مرحلة

### المرحلة 0 — الأساس ومفاتيح API

1. أنشئ مفتاح API من «الإعدادات → مفاتيح API» مع scope ومعدل دقيق/دقيقة.
2. `curl -H "Authorization: Bearer omnirag_live_..." <APP_URL>/api/v1/documents` → 200.
3. مفتاح خاطئ → 401؛ مفتاح مُبطَل → 401؛ تجاوز الحد → 429.

### المرحلة 1 — المزودون

1. «الإعدادات → المزودون»: أضف اعتمادات OpenAI (أو Ollama المحلي `http://host:11434`).
2. زر «اختبار اتصال» لكل مزود.
3. من «نماذج الإعدادات» اختر نموذج OpenAI للدردشة وآخر للتضمين.
4. دردشة قصيرة → الرد من المزود الجديد (تحقق من السجلات).
5. مرجع قديم غير مؤهل (اسم نموذج Gemini مجرد) ما زال يعمل — توافق رجعي.

### المرحلة 2 — التخزين

1. «الإعدادات → التخزين»: بدّل مخزن المتجهات إلى pgvector.
2. أعد فهرسة مستند (`reindex`) ثم ابحث دلاليًا — النتائج تعمل.
3. ارفع ملفًا مع `ARCHIVE_UPLOADS=true` وتحقق من وجوده في مخزن الكائنات.

### المرحلة 3 — الموصلات والطوابير

1. «إضافة مصدر»: المعالجة تُبنى ديناميكيًا من السجل لكل نوع.
2. جرّب موصلًا جديدًا (Notion/GitHub/SQL قراءة فقط) + «اختبار اتصال».
3. جدولة مزامنة (كل 30 دقيقة) وانتظر دورة العامل (Docker) أو الـ tick (Vercel).
4. استوديو الابتلاع: بدّل محرك الاستخراج (Mistral OCR/Unstructured/محلي) ولاحظ السجل.
5. عدّل مصدرًا: الحقول المقنّعة `••••••••` تُحفظ كما هي ولا تكتب فوق السر.

### المرحلة 4 — مهارات الدردشة

1. دردشة مع بث حي (الكلمات تظهر تدريجيًا) واطلب:
   - `create_chart` → مخطط تفاعلي في الرسالة.
   - إنشاء ملف Word/Excel/PPT → رابط تنزيل يعمل.
   - `build_report` → تقرير منظم.
   - إرسال بريد (مع SMTP مُعد) → **نافذة تأكيد إلزامية** قبل الإرسال.
2. MCP: زر OAuth لخادم يدعمه، وأضف خادم stdio محلي (Docker فقط).

### المرحلة 5 — الفرق والصلاحيات وSSO

1. ادعُ عضوًا بدور viewer → جرّب أن يعدّل مستندًا → يُرفض.
2. رابط دعوة `?invite=TOKEN` → تسجيل ينضم للمساحة بدل إنشاء مستأجر.
3. شارك مجموعة برابط قراءة فقط → يفتح بدون تسجيل.
4. أعد SSO ضد أي issuer (Keycloak محلي مثلًا) → تسجيل دخول JIT.
5. مبدّل مساحات العمل في الترويسة يبدّل الجلسة فعليًا.

### المرحلة 6 — التكامل الخارجي

1. افتح `/api/docs` وجرّب مسارًا بالمفتاح.
2. أضف `/api/v1/webhooks` نقطة نهاية بسر توقيع، ثم فهرس مستندًا →
   يصل حدث `document.indexed` بتوقيع HMAC صحيح.
3. وصّل Claude Desktop/Cursor بخادم MCP الصادر:
   ```json
   {
     "mcpServers": {
       "omnirag": { "url": "<APP_URL>/api/mcp", "headers": { "Authorization": "Bearer omnirag_live_..." } }
     }
   }
   ```
   وقلّص الأدوات المسموحة لهذا المفتاح (`mcp_tools`) وتحقق من enforcement.

### المرحلة 7 — i18n والخطط

1. بدّل اللغة من الترويسة — كل الواجهة (دردشة، معرفة، إعدادات، تشخيصات،
   معالجات الإضافة) تتبدل فورًا وتُحفظ بعد إعادة التحميل.
2. «الإعدادات → الخطط»: غيّر خطة المستأجر وجرّب تجاوز حصة (أعضاء/مستندات/
   موصلات) → رسالة حصة واضحة.

## 8) ملاحظات أمان لا تُكسر عند النشر

- مفاتيح API: يُخزن SHA-256 hash فقط؛ النص الصريح يظهر مرة واحدة.
- `MCP_OAUTH_ENCRYPTION_KEY` إلزامي في الإنتاج (التطبيق يرفض البدء بدونه
  في عمليات التشفير).
- `/api/v1/jobs/tick` يُرفض في الإنتاج بدون `CRON_SECRET`/`JOBS_TICK_SECRET`.
- stdio مزدوج البوابة (self-hosted فقط) وقيم env الخاصة به مشفرة.
- موصل SQL يبقى **قراءة فقط**؛ حراس SSRF في `net.ts` حدود أمنية لا تُضعَّف.
- `ALLOW_CLIENT_ENV` مرفوض افتراضيًا في الإنتاج.
- الطوابع الزمنية varchar(100) ISO — قرار موثق، لا «تصلحه».
